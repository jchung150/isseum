# 대관 신청 → 구글 시트 연동

`Code.gs`를 예약 신청이 쌓일 구글 시트에 붙여넣고 웹앱으로 배포하면,
Cloudflare Worker가 이 주소로 신청 내용을 보냅니다.

## 설치 순서

### 1. 스크립트 붙여넣기

1. 신청서가 쌓일 구글 시트를 엽니다
2. 상단 메뉴 **확장 프로그램 → Apps Script**
3. 기본으로 있는 `Code.gs` 내용을 **전부 지우고** 이 폴더의 `Code.gs` 내용을 붙여넣습니다
4. 저장 (⌘S)

### 2. 최초 설정 실행

1. 함수 선택 드롭다운에서 **`setup`** 을 고르고 **실행**
2. 처음 실행하면 권한 승인 창이 뜹니다 — 본인 계정으로 허용합니다
   - "이 앱은 확인되지 않았습니다" 경고가 나오면 **고급 → 안전하지 않음(이동)** 을 눌러 진행합니다.
     본인이 작성한 스크립트라 정상입니다
3. 실행이 끝나면 **실행 로그**에 `SHARED_SECRET = ...` 값이 찍힙니다

이 값을 복사해 두세요. **이 값은 채팅에 붙여넣지 마세요.** 나중에 아래 명령으로 직접 등록합니다:

```bash
npx wrangler secret put SHEET_SECRET
```

`setup`은 시트 첫 행에 헤더를 만들고 굵게 처리한 뒤 고정합니다. 이미 헤더가 있으면 건드리지 않습니다.

### 3. 웹앱으로 배포

1. 우측 상단 **배포 → 새 배포**
2. 톱니바퀴 → **웹 앱** 선택
3. 설정:

| 항목 | 값 |
|---|---|
| 설명 | `isseum booking` |
| 다음 사용자 인증 정보로 실행 | **나** |
| 액세스 권한이 있는 사용자 | **모든 사용자** |

4. **배포** → 나오는 **웹 앱 URL** 을 복사

URL은 `https://script.google.com/macros/s/…/exec` 형태입니다.
이건 시크릿이 아니라 주소이므로 알려주셔도 됩니다.

> **"모든 사용자"로 두는 이유** — Cloudflare Worker는 구글 계정으로 로그인할 수
> 없습니다. 대신 요청 본문의 `secret` 값이 일치할 때만 기록하므로, 주소를 알아도
> 시크릿 없이는 아무것도 쓸 수 없습니다.

### 4. 코드 수정 후에는 다시 배포

Apps Script는 저장만으로 반영되지 않습니다. 코드를 고쳤다면
**배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포** 를 해야 적용됩니다.
URL은 그대로 유지됩니다.

## 저장되는 항목

접수 일시 · 성함 · 소속 · 전화번호 · 이메일 · 대관 날짜 · 시작 · 종료 · 시간 ·
총 인원 · 대관 설명 · 유입 경로 · 추가 옵션 · 요청 사항 · 규정 동의 ·
개인정보 동의 · IP · User-Agent

- **유입 경로 / 추가 옵션** 은 복수 선택이라 ` · ` 로 이어 한 칸에 넣습니다
- **IP / User-Agent** 는 동의 시점의 증빙용입니다. 개인정보이므로 보유 기간(3년)이
  지나면 함께 파기해야 합니다

## 실패해도 문의는 남습니다

Worker는 **메일을 먼저 보내고** 시트 기록을 시도합니다. 이 스크립트가 오류를 내거나
구글 장애로 응답하지 않아도 알림 메일에는 신청 내용 전체가 들어 있습니다.
시트는 관리 편의를 위한 사본이지 유일한 기록이 아닙니다.

## 헤더를 바꾸고 싶다면

`HEADERS` 배열과 `doPost` 의 `appendRow` 순서를 **함께** 고쳐야 합니다.
기존 데이터와 어긋나므로 **열을 중간에 끼워 넣지 말고 뒤에 추가**하세요.
